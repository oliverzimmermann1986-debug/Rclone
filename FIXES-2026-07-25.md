# Fehler- und Performancekorrekturen vom 25.07.2026

## Datenbank

- Der einmalige Backfill der Pair-Historie iteriert nun über den SQLite-Cursor,
  statt alle Jobs mit `fetchall()` gleichzeitig in den Arbeitsspeicher zu laden.
- Die Migration arbeitet mit Savepoints in Blöcken von 500 erfolgreich
  verarbeiteten Datensätzen und rollt den aktuellen Block bei Fehlern sauber zurück.

## API / Backend

- `/api/diagnostics/overview` besitzt nun einen threadsicheren Kurzzeit-Cache von
  acht Sekunden. Mehrere Tabs teilen sich dadurch die teuren DB-, Cron-, systemd-
  und Systemabfragen.
- Cache-Antworten werden kopiert, damit nachgelagerte Änderungen den gecachten
  Zustand nicht mutieren können.
- Beim Start werden unsichere Web-Defaults deutlich geloggt.
- `/readyz` meldet zusätzlich `warnings` und `secure_configuration`, bleibt bei
  technisch betriebsbereiter lokaler HTTP-Konfiguration aber kompatibel mit HTTP 200.

## GUI

- Vollständige Hintergrundaktualisierung wurde von 15 auf 30 Sekunden reduziert.
- Die teure Betriebsübersicht wird nur noch geladen, wenn das Dashboard sichtbar ist.
- In inaktiven Browser-Tabs werden Polling-Timer vollständig beendet und beim
  Zurückkehren neu gestartet.
- Aktivitäts-Polling arbeitet adaptiv: zwei Sekunden während laufender Jobs,
  ansonsten zehn Sekunden.
- Doppelte Polling-Schleifen werden verhindert.
