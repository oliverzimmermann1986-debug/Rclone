## Brief inference

Infer direction from the product category, audience, content, brand evidence, conversion goal, and existing interface. Name the evidence behind the direction. Do not select a fashionable style before understanding the job.

Use a specific archetype such as editorial utility, calm premium, technical instrument, playful consumer, industrial brutalism, or institutional clarity. Combine at most two compatible archetypes.

## Three control dials

Set three qualitative dials and use them consistently:

- **Design variance**: familiar and restrained → unusual and art-directed
- **Motion intensity**: nearly static → expressive and cinematic
- **Visual density**: spacious and selective → compact and information-rich

Raise variance only where the user's risk tolerance and product context support it. Keep transaction-heavy and frequently used interfaces more predictable than marketing moments.

## System construction

Build semantic roles instead of scattered values:

- background, surface, elevated surface, text, muted text, border, accent, success, warning, danger
- display, heading, body, label, code, and data typography roles
- spacing steps that create recognizable rhythm
- component states for hover, focus, active, disabled, loading, selected, and error
- responsive rules based on content pressure rather than device labels alone

Use type and spacing as the primary hierarchy tools. Keep body text comfortably readable and line lengths controlled. Treat contrast, focus visibility, target size, and zoom behavior as design qualities.

## Page and component craft

Give each major section one clear job. Vary composition through content needs, not randomization. Alternate density and scale to create rhythm while preserving a common grid.

Prefer:

- a clear primary action
- strong alignment and deliberate whitespace
- purposeful imagery with consistent treatment
- a small number of component families
- explicit empty, loading, success, and error states
- content that sounds specific to the product

Question:

- cards used only to create grouping
- gradients without a lighting or brand rationale
- excessive pills and badges
- nested containers with repeated borders
- decorative charts or invented statistics
- huge headlines that damage comprehension
- indistinguishable sections with identical layouts

These are not absolute bans. Keep a pattern when it solves a real information or interaction problem.

## Redesign discipline

Audit before editing. Separate:

1. broken usability or accessibility
2. weak hierarchy and content structure
3. inconsistent system decisions
4. dated but functional styling
5. optional expressive polish

Preserve routes, data behavior, terminology, analytics hooks, and interaction contracts unless the user authorizes changes. Decide explicitly between targeted evolution and full redesign.

## Image-led work

Use image generation for visual exploration, art direction, or a requested reference board. Keep images legible enough to inspect. For multi-section concepts, prefer section-specific references over one compressed collage.

When implementing from an image, extract grid, typography, spacing, color roles, media treatment, component states, and responsive intent. Reconstruct the system rather than tracing pixels blindly. Resolve missing interaction and mobile details explicitly.
